# Repository instructions

## Start here

This repository archives Microsoft's certified Power Query (M) connector source
and publishes it as an Open Knowledge Format (OKF) v0.3 bundle.

| To | Go to |
| --- | --- |
| Write, extend, or review a connector to production grade | Skill: `skills/write-connector` (Microsoft SDK steps, quality bar, pitfalls). Evidence: `bundle/topics/`. Microsoft's own sample connectors and SDK test queries (MIT, meant to be copied): `reference/microsoft-dataconnectors/`. Self-checks: `uv run pqkb certification --path <folder>`, `uv run pqkb functions --path <folder>`. |
| Find how connectors implement something | `bundle/index.md`, then `bundle/topics/` (one per SDK concept, linking its patterns in `bundle/patterns/`) and `bundle/connectors/`; source in `connectors/<Name>/`. Skill: `skills/find-connector-code`. |
| Search the bundle through MCP | `.mcp.json` runs okf-mcp on `bundle/` (search, neighbors, provenance). |
| Refresh the archive or fix a refresh PR | Skill: `skills/refresh-archive`. |
| Renew a drifted pattern page | Skill: `skills/review-pattern`. |
| Run or retry LLM candidate reviews | Skill: `skills/run-candidate-reviews`. |
| Write, validate, or read OKF | Official skills: `skills/okf-generate` (validator: `scripts/validate.py`), `skills/okf-consume`. |

The skills are also packaged as a plugin (`.claude-plugin/marketplace.json`,
`.agents/plugins/marketplace.json`); `.claude/settings.json` pre-registers it.

## CodeScene

After changing code, run `code_health_review` on the changed files. If Code
Health drops, fix the issues, run the review again, and use `code_health_score`
to confirm the result. Target Code Health 10.0, as required by the parent
instructions. Before finishing, run `pre_commit_code_health_safeguard` and
resolve reported regressions. Run `analyze_change_set` before opening a PR.

## Generated knowledge

- Authored pattern pages, candidate assessments, and the refresh log live in
  `knowledge/`. Edit pattern explanations only in `knowledge/patterns/`. Which topic
  and checklist answers each pattern explains is set in `knowledge/topics.yaml`.
- `bundle/` is generated by `uv run pqkb build` and committed so agents can
  browse it. Never edit it by hand; change `knowledge/` or `src/pqkb/` and
  rebuild. CI fails if a rebuild changes `knowledge/` or `bundle/`.
- Never hard-code the repository's name or URLs. `src/pqkb/repo.py` derives them
  (`GITHUB_REPOSITORY` in CI, else the origin remote). Pattern pages cite
  `connectors/<Name>/<file>#L<n>`, and the build turns that into a GitHub URL.
  Review fingerprints don't depend on the name, so a rename keeps reviews valid.
  Files that must hold literal URLs (README, plugin manifests, settings) are
  checked by `tests/test_repo.py`; after a rename, update them and rebuild.
- `skills/okf-generate` and `skills/okf-consume` are vendored unmodified from
  the OKF repository, and `src/pqkb/viz` with import-path edits only; re-sync
  them instead of editing (`skills/VENDORED.md`, `src/pqkb/viz/VENDORED.md`).

## Reviews

- The user delegated source review to agents and requested hands-off
  maintenance. Nothing about documentation blocks a refresh or publication.
- When cited connector source or reviewed page content changes, the page's
  review is drifted: `pqkb verify-reviews` reports it and the build marks the
  page's copy in `bundle/` with OKF `stale_after` and a banner. The authored file
  is never rewritten by a build.
- An agent may renew a drifted page only after checking every claim against its
  cited source (`skills/review-pattern`), recording its own actor identity with
  `reviews.record_review(repo, path, reviewer, now)`. Never call it merely to
  make a check pass, and never attribute human verification to an agent or a
  deterministic check.
- LLM candidate reviews (`knowledge/match-reviews.json`) are advisory labels on
  connector pages and never renew pattern reviews.
